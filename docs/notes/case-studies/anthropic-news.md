# Case study: anthropic.com/news (a site with no feed)

Investigated 2026-09-15 with plain `curl` (no browser, no JavaScript). Findings are a snapshot; the site can change.

## What's there and what isn't
| Signal | Found? | Details |
|---|---|---|
| RSS/Atom feed | ❌ | No `<link rel="alternate">`; `/rss.xml`, `/feed`, `/atom.xml`, `/news/rss.xml` etc. all 404 |
| robots.txt | ✅ | `Allow: /` for all agents, points to sitemap |
| Sitemap | ✅ | `/sitemap.xml`, **257 `/news/` URLs**, each with `<lastmod>` |
| JSON-LD (schema.org) | ❌ | None on listing or article pages |
| Open Graph | ⚠️ | Title, description, image present; `og:type` is `website` (not `article`); **no published date** |
| `<time>` tags | ⚠️ | Present, but **no `datetime` attribute**; only display text like `Sep 1, 2026` |
| Server-rendered HTML | ✅ | Posts are in the initial HTML; no browser needed to see the first page of results |
| Embedded CMS data | ✅ (undocumented) | Next.js RSC payload contains Sanity CMS records with `slug.current` and ISO `publishedOn` |
| HTTP caching | ❌ | `cache-control: no-store`, no `ETag`/`Last-Modified` → every check downloads the full page |
| Bot protection | ✅ passes | Behind Cloudflare, but a plain `curl` with a browser user agent got `200` |

## Tech stack clues
- **Next.js (App Router):** `self.__next_f` script chunks (React Server Components payload).
- **Sanity CMS:** 269 references to `cdn.sanity.io`.
- **CSS Modules with hashed class names:** `PublicationList-module-scss-module__KxYrHG__date`. The `KxYrHG` part is a build hash.

## Page weight
- HTML: ~465 KB, of which **~415 KB is script** (89%).
- Visible text: **~3.9k characters**.
- Lesson: feeding the raw page to an LLM would waste >99% of tokens. Extract first.

## Traps found
1. **Hashed class names.** A selector like `.PublicationList-module-scss-module__KxYrHG__date` breaks whenever the build hash changes, even with no visual redesign. A pattern match on the stable part (`[class*="PublicationList"][class*="__date"]`) survives longer, but still depends on component names.
2. **Two lists on one page.** A "featured" grid (5 items) and a publication list (10 items) share posts. Naive scraping double-counts.
3. **Featured grid is not chronological.** Order: Sep 1, Sep 10, Aug 31, Aug 27, Jul 24. "First item = newest" is wrong here.
4. **Featured ≠ subset of the list.** The Sep 10 featured post isn't in the top 10 of the publication list. Scraping only one section can miss posts.
5. **Human-format dates.** `Sep 1, 2026` has no time zone and needs locale-aware parsing.
6. **Listing only shows ~10 recent posts** (then a "See more" button). If a check is missed and more than ~10 posts appear, the listing alone would miss some.
7. **Sitemap `lastmod` = last edit, not publish date.** Many entries share one timestamp (`2026-09-15T16:26:48.351Z`, 27 URLs), i.e. regeneration time. `lastmod` can't be trusted as "new."

## Ways to detect new posts here, ranked
| Approach | Level | Stability | Cost per check | Notes |
|---|---|---|---|---|
| **Sitemap diff:** new `/news/` URL not seen before = new post | 1-ish | High (generated by the site) | ~70 KB | Ignore `lastmod`; compare URL sets. Doesn't give title/date → fetch the post page |
| **Embedded CMS data** (`publishedOn`, `slug`) | 3 | Medium: undocumented, changes with framework/CMS upgrades | ~465 KB | Clean ISO dates; parsing the RSC format is awkward |
| **Links + dates from HTML** by URL pattern (`href="/news/…"`), not class names | 3 | Medium-high | ~465 KB | URL structure changes much less often than CSS |
| **CSS selectors** on hashed class names | 3 | Low | ~465 KB | The classic brittle approach |
| **LLM reads the extracted page text** | 3 + LLM | High for interpretation | ~465 KB + tokens | Resilient to markup changes; needs output validation |
| **Headless browser** (to click "See more") | 4 | Medium | Heavy | Not needed for regular checks here |

## Takeaways
- "No RSS" does not mean "must scrape HTML." Check robots.txt → sitemap → embedded data → HTML → browser, in that order.
- The sitemap + URL-set diff is a strong, general method for feedless sites.
- Anchor on **URL patterns and meaning**, not presentation (class names, position).
- This site doesn't need an agent to *detect* posts. An agent helps with the **one-time investigation** (the steps done manually here) and with **recovery when the recipe breaks**.
